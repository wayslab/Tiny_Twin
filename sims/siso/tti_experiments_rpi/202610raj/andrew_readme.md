# 202610raj — how to run (succinct)

6 scenarios: path A/B × gt/2nn/nerf, driven by AI53_017 CIR data.

## Paths
```
RPI=/home/ways_lab/repos/Tiny_Twin/sims/siso/tti_experiments_rpi
EXP=$RPI/202610raj
VENV=/home/ways_lab/repos/venv/sub6isac_env
GEN=/home/ways_lab/repos/Tiny_Twin/channel/raj_chan/20261009/generate_20261009.py
```

## 1. Build channels (once; re-run if the zip or warmup/tail params change)
```bash
source $VENV/bin/activate
python3 $GEN        # -> channel/raj_chan/20261009/channel_{gt,2nn,nerf}_{A,B}.txt
```

## 2. Isolate CPU — EVERY boot, before running (resets on reboot)
```bash
sudo $RPI/setup_cpu_isolation.sh
cat /sys/fs/cgroup/system.slice/cpuset.cpus.effective   # must be 0-4,10-14, else MCS pins at 6
```

## 3. Keep nr-softmodem at real-time priority (background, during the run)
```bash
sudo bash -c 'end=$((SECONDS+3000)); while [ $SECONDS -lt $end ]; do
  for p in $(pgrep -f nr-softmodem); do chrt -p "$p"|grep -q FIFO||chrt -f -p 80 "$p"; done
  pgrep -f run_six_scenarios >/dev/null || break; sleep 2; done' &
```

## 4. Run (one SNR anchor at a time, re-isolate before each)
```bash
source $VENV/bin/activate && cd $EXP
./run_six_scenarios.sh 45 ./plot/snr-45dB_lw 280    # <SNR> <outdir> <duration_s>
```
Re-isolate (step 2) + re-run for 40 and 35. Only 35-45 dB were run (30 dB links
too marginal). `run_one_snr.sh <SNR>` (in scratchpad) does steps 2-4 for one
anchor. Duration 280 s is sized for the ~0.6x real-time rate (see below).

## 5. Verify + plot
```bash
# MCS/DL/UL per scenario:
for s in pathA_gt pathA_2nn pathA_nerf pathB_gt pathB_2nn pathB_nerf; do
  awk '/^UL MCS:/{n++;s+=$3;if($3>m)m=$3} END{printf "%-11s mean=%.1f max=%d\n","'"$s"'",s/n,m}' \
    plot/snr-30dB_lw/$s/snr.txt; done
python3 plot_channel_strength.py 45 ./plot/snr-45dB_lw/channel_signal_strength_45dB.png
```
Multiplot is auto-generated by the run (`plot/<out>/multiplot.png`). ALSO check
coverage: last `TTI Index` in each snr.txt should reach `120000 + motion_rows`
(~338001); if it stops early, the UL collapsed (see below). Results +
per-scenario coverage table: `plot/COVERAGE_NOTES.md`.

## What we had to figure out (the non-obvious parts)

- **CPU isolation each boot, or MCS pins at 6.** `setup_cpu_isolation.sh` evicts
  host tasks/IRQs off the OAI cores (5-9,15-19); effects reset on reboot. Plus
  FIFO:80 on nr-softmodem (step 3). Without both, scheduler jitter -> ~10% BLER
  floor -> UL MCS stuck at 6.

- **Early tap = MAX start of all sets, held 60 s.** The channel's own first
  sample is too weak to attach at low anchors (nerf 0.034 -> 0.55 dB @ 30 dB).
  The warmup holds the STRONGEST starting tap across all 6 traces (0.1037 ->
  ~10/15/25 dB @ 30/35/45) so every scenario attaches. It must be held ~60 s
  (`WARMUP_TTI=120000`), NOT shorter: 15 s and 40 s warmups collapsed the UL
  mid-warmup (TCP didn't reach steady state before motion). 60 s settles it.

- **End tap = hold to the end (so the channel never runs out).** A tail that
  holds the last sample (`TAIL_TTI`) keeps the channel valid through the whole
  run; without it the gNB exhausts the file mid-run.

- **rfsim runs ~0.6x real-time -> size duration to SIM-TIME, not wall-clock.**
  The channel advances 1 row per TTI (0.5 ms of sim-time), but under the iperf
  load rfsim only does ~1077 TTI/s (vs 2000/s real-time). So a wall-clock
  `--duration` plays only ~0.6x as much channel. To play the full ~109 s motion
  you need ~180 s of traffic + the warmup budget => we use duration ~280 s.
  Rule: `duration_s >= (warmup_rows + motion_rows) / ~1077 - setup(~35s)`.
  Check coverage: last `TTI Index` in snr.txt should reach
  `WARMUP_TTI + motion_rows` (motion fully played).

- **Saturating-TCP UL collapses on weak links (known limit).** On a weak/
  deep-fading link the single `sat` TCP UL stream eventually resets and never
  reconnects (UL -> 0 for the rest of the run). Measure survival by ACTUAL UL
  goodput, NOT snr.txt TTI coverage: after the reset the connection stays alive
  retransmitting, so MCS keeps logging to ~full TTI coverage while goodput is 0.
  It is probabilistic (more likely on weaker links, but timing varies per run):
  e.g. pathB_2nn survived 35 dB yet collapsed at 40 dB. Only pathB_nerf survived
  all 3 anchors; pathA_nerf collapsed at all 3. We kept TCP and accept this. For
  full coverage, switch UL to UDP (connectionless, never resets). Real
  per-scenario survival table: `plot/COVERAGE_NOTES.md`.
